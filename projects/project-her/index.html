    How it works

    1. 01 · InputSubmit a topic, a supplied story, or a public article URL. News can research or respect supplied facts.
    2. 02 · ScriptContent processing and Gemini prepare source-linked narration and scene subjects.
    3. 03 · Voice & timingTTS produces speech. Provider marks or forced alignment anchor text to the audio.
    4. 04 · Visual assetsRelevant portraits, reference media and disclosed illustrations are retrieved or generated.
    5. 05 · CompositionRemotion composes timed layers. FFmpeg processes the media and validates delivery.

    The portfolio sends jobs to the HER backend on Cloud Run. Rendering stays there; the static portfolio never renders video in its page or build process.

    Engineering the complete workflow

    The problem & my contribution

    A short video requires more than a model response: a usable script, relevant visuals, narration, captions, scene transitions and a playable export. Article quality and available media vary, so every handoff affects the result.

    This is my personal build, separate from employer-owned engineering work and hackathon prototypes. I connected content processing, media preparation, audio timing, programmatic composition and a deployed application. The native studio brings that workflow into the portfolio while keeping rendering and provider credentials on the backend.

    Architecture: a native client and an isolated rendering backend

    This portfolio uses static HTML, CSS and JavaScript on GitHub Pages. A typed JavaScript client submits HTTPS jobs to a scoped Flask API on Cloud Run. Flask/Gunicorn coordinate the Python pipeline; React is used by Remotion compositions. No iframe or redirect is involved in creation.

    News/editorial uses Pydantic plans, source and asset provenance, timed narration and independent frame layers. Classic uses the existing general orchestrator. The adapter validates the supported public options rather than passing arbitrary model names or filesystem paths to the engine.

    Async jobs, synchronization & reliable delivery

    Real stage changes arrive through authenticated fetch-based SSE, with polling of the same job record when a stream disconnects. A scoped job token supports recovery in the current browser tab. Only backend-confirmed completion reveals the generated player; a playable video must load before its download appears.

    The native API adds transactional durable job/quota records and private Cloud Storage output. Expiring media tickets authorize byte-range playback and downloads. Production needs those services provisioned before generation can be enabled; the studio reports an honest unavailable state otherwise. Accepted paid work is not automatically replayed after a worker restart.

    Speech, scene boundaries and text reveals share the audio clock. Sample-accurate decoded PCM assembly avoids MP3 duration/padding errors. Replicate speech requests are paced and rate-limit retries preserve the provider. Alignment confidence and illustration provenance remain inspectable, without claiming perfect synchronization or historical fidelity.

    Cost, security & failure boundaries

    Anonymous jobs have server-enforced input/duration limits, shared daily and network-identity quotas, a global concurrent-render limit and a kill switch. Article retrieval validates resolved public addresses and each redirect. Provider keys stay on the server; one job token cannot access another visitor’s output. Production also locks the old public generation/history/output endpoints to operator access so they cannot bypass the native safeguards.

    URL extraction, media relevance, third-party quotas and factual accuracy remain fallible. Classic does not support cancellation; News does. A cancellation request is not reported as completed until the backend confirms it. Render times and availability depend on inputs and external services; no throughput, uptime or quality guarantee is implied.

    Evidence, deployment & current limitations

    The previously generated example is a byte-identical local HER Remotion artifact with measured 1080×1920, 30fps H.264/AAC output and saved source/narration provenance. It is not evidence of a newly executed public job.

    The studio checks the native API before enabling generation. Source-level contract, fixture and responsive checks are distinct from a production end-to-end generation test. A reachable Cloud Run landing page alone does not establish that live generation works.
